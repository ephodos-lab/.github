# Contributing to Ephodos Lab projects

Thank you for your interest. These guidelines apply to every repository in the organization unless that repository has its own CONTRIBUTING file.

## Before you start

- Search the existing issues first; your question or idea may already be there.
- For anything bigger than a small fix, open an issue and discuss it before writing code.

## Reporting a bug

Open an issue and include:

- what you did, what you expected, and what happened instead;
- your environment: operating system, Python or Node version, and the model and provider if the bug involves an AI agent;
- logs or error output.

Remove API keys, tokens, passwords and private data from anything you paste.

## Pull requests

1. Fork the repository and create a branch from the default branch.
2. Keep each pull request to one change, and add or update tests where the project has them.
3. Describe what changed and why, and link the issue it addresses.
4. Make sure the test suite passes before asking for review.

## Changes that affect mathematics

If your change touches a proof, a prompt that produces or reviews proofs, or a review step, say in the pull request how you checked that it still behaves correctly.

## Language

Issues and pull requests may be written in English or Chinese.

## Licence

By contributing, you agree that your contribution is licensed under the licence of the repository you contribute to.
